# FreshSense

Food spoilage triage. A fine-tuned ViT decides *fresh* vs *spoiled* from a
photograph; a guard-railed agent grounds that decision in a food-safety
knowledge base and turns it into an auditable recommendation.

Decision support for a trained operator — never a clearance to release food.

```
ingest ─► classify ─► retrieve ─┬─(model has a signal)─► explain (Claude) ─┐
                                └─(model is guessing)──► offline ──────────┴─► guard ─► finalise
```

## The result worth knowing

On the held-out test split (129 images), the raw model misses one spoiled item —
`spoiled_recall` 0.967. Under the deployed asymmetric safety policy, **zero
spoiled items are released as fresh**: that case falls into the abstain band and
routes to a human, at a cost of a 1.6% abstention rate.

Probabilities are not verdicts. Condemning food needs weak evidence; clearing it
needs strong evidence. Full numbers and limitations in
[`docs/MODEL_CARD.md`](docs/MODEL_CARD.md).

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev,llm]"

make model                          # export the head checkpoint (8.2 KB)
freshsense assess path/to/food.jpg --hint "strawberries"
```

```
  verdict    SPOILED  (47.1% confident)
  action     discard
  policy     p(spoiled)=0.47 at or above the 0.30 safety threshold; spoilage is
             condemned on weak evidence by design.

  Strawberries: The classifier found visible indicators of spoilage in this
  image (p(spoiled)=0.47). Under the service's safety policy, spoilage is acted
  on even at modest confidence, so this item is condemned on appearance.

  Next steps: Do not taste the item. Isolate it from surrounding stock, bag it
  before disposal, then clean and sanitise every surface it touched. Inspect
  adjacent items on the same shelf.

  Sources:
    - 04-disposition-and-handling#1   Disposition and handling procedure
    - 01-visual-spoilage-indicators#4 Visual indicators — Texture change

  [offline explainer, 5705 ms]
```

Note that verdict: at p(spoiled)=0.47, plain `argmax` would have called this
item **fresh**. The policy is the reason it did not.

## Running the service

```bash
make serve                          # http://localhost:8000/docs
```

```bash
curl -X POST http://localhost:8000/v1/assess \
     -F image=@food.jpg -F food_hint=strawberries
```

Returns the verdict, the action, the probabilities, the policy note, the
grounded explanation with citations, any guardrail notes, and a per-node
execution trace — everything needed to reconstruct the decision later.

```bash
docker compose up --build           # non-root, read-only, healthchecked
```

## With and without an API key

Nothing here requires one. Unset, `ANTHROPIC_API_KEY` selects a deterministic
offline explainer that produces a complete, cited, guard-railed explanation with
no network — a supported mode, not a stub. Set it, and explanations are
generated by Claude, subject to the same guardrails, with an automatic fallback
to the offline path on any failure.

```bash
export ANTHROPIC_API_KEY=sk-ant-...   # optional
```

## Layout

```
src/freshsense/
  config.py         typed settings; rejects a policy that can never abstain
  domain.py         framework-free dataclasses shared by every layer
  vision/           ViT, transforms, head-only checkpoints, decision policy
  genai/            retrieval, versioned prompts, LLM client, guardrails
  agent/            reusable state-graph runtime + the triage workflow
  api/              FastAPI, request-id middleware, health and readiness
kb/                 the food-safety knowledge base (5 documents, 13 chunks)
tests/              133 fast + 9 integration
docs/               model card, architecture, JD mapping
```

## Provenance

Grown out of `pD_final.ipynb` in the root of this repository, a Colab notebook
that trains this classifier to 98.4% validation accuracy. The notebook is still
the experiment; this directory is what it looks like once it has to survive
contact with production.

It sits alongside the `backend/` + `frontend/` + `nginx/` deployment at the repo
root, which serves the same model through a simpler predict endpoint. The
dataset and preprocessing pipeline live in the companion repository
[PD-lab](https://github.com/Krishna-web-hub/PD-lab).
